# PROJECT-SPECIFIC LEARNINGS

Session-derived facts that are not recoverable by reading the code alone. Update these as the product evolves.

## Database & Prisma

- `scripts/switch-provider.ts` rewrites the datasource `provider` line in `prisma/schema.prisma` IN PLACE from `DATABASE_URL` (sqlite / postgresql / cockroachdb). Never hand-edit that line — it is overwritten on every build (`bun run build` runs it first).
- The generated Prisma client can lag the schema: models added to `schema.prisma` throw `Model 'X' does not exist on active client` until `bun run db:generate` runs (observed with `Recording` on the dev SQLite client). Run `db:generate` after any schema edit.
- Schema changes ship as flat SQL files under `prisma/migrations/*.sql`, applied by `bun run db:sqlmigrate` (`scripts/apply-sql-migrations.ts`). `prisma migrate dev` is NOT the workflow; `db:seed` runs the SQL migrator first. A schema field and its SQL migration must land together.
- `Composition` persists only `source` (source_attribution string) — `sourceUrl`/`sourceAttribution` fields are dropped at import persist. Verifiers (e.g. `verify-santsahitya`) must reconstruct live URLs from `titleTranslit`.

## Catalog Reality (as of Aug 2026)

- ~26,300 compositions + ~554 `CompositionVersion` variants from 20 `ContentSource` rows — the archive is lyrics-first. In contrast: saints=4, temples=0, festivals=2, playlists=0. Entity pages therefore render near-empty until saints/temples/festivals get seeded.
- `/learn` and `/wari` pages are hardcoded client components (JOURNEY_STOPS, TIMELINE_EVENTS arrays) with zero DB fetches — content lives in the component, not the database.

## Importers & Dedup

- Cross-edition abhang numbering is NOT consistent: santsahitya `krmank` numbers ≠ Wikisource global Gatha numbers ≠ santvani section numbers. Match by verse text / first meaningful line, never by title number.
- The two-stage fuzzy matcher (trigram first-line index → bigram Dice + Levenshtein confirm) lives in `scripts/import-archive-variants.ts` and is reused by `link-import-variants` and `add-gatha-numbers`. Confirmed matches become `CompositionVersion` rows; unconfirmed rows stay standalone (platform forbids silent misidentification).
- All `acquire:*` / `lyrics:*` scripts default to `--dry-run` and support checkpoint/resume; run in ~250-page windows. Importer dedup = content-hash (pipeline) + canonical-title page check.

## Tooling & Git

- `git commit` includes ALL staged changes: pre-existing staged deletions (e.g. `components/search-results.tsx`) get swept into unrelated commits. Inspect the full staged set with `git status --short` before committing; unstage unrelated items and re-stage them afterward.
- `.freebuff/` is gitignored — one-off inspection/verify scripts belong there (bun cannot resolve Git Bash `/tmp` paths; keep scratch files project-relative).
- Gates: `bun run typecheck` = `tsc --noEmit`; lint enforces `--max-warnings 0`; unit tests = `bun test tests/unit/`. `docs/openapi/audio-platform.yaml` must stay in sync with `app/api` routes (`bun run doc:lint`).
